# Лаб 3: Чанарын сценарио → SLO → k6 threshold

Тестлэх бай: өөрийн локал Express API (`server.js`, http://localhost:3000). Гадаад сайт руу тест хийгээгүй.

## Сценарио 1. Performance: /cart/add-ийн хариу хугацаа

| Хэсэг | Агуулга |
|---|---|
| Тойм | Хэрэглэгч сагсандаа бараа нэмэхэд систем хурдан хариулна. |
| Системийн төлөв | Серверийн нэг процесс ажиллаж байна, бүх endpoint хэвийн, өмнөх тест үлдээсэн ачаалал байхгүй. |
| Орчны төлөв | Хэвийн ачаалал: 20 зэрэгцээ хэрэглэгч (VU), VU бүр 1 секунд тутамд 1 удаа, нийт ойролцоогоор 20 хүсэлт/с. Тест 1 минут үргэлжилнэ. |
| Гадаад өдөөлт | Хэрэглэгч `POST /cart/add` хүсэлт илгээнэ. |
| Шаардлагатай хариу | Систем 200 статусаар `{ok:true}` буцаана. |
| Хэмжүүр | 95% хүсэлт 100 мс-ээс бага (p95 < 100 мс), 99% хүсэлт 250 мс-ээс бага (p99 < 250 мс). |

SLO: `/cart/add` p95 < 100 мс, p99 < 250 мс (20 VU, ~20 req/s). Эдгээр тоо урьдчилсан. Алхам 3-д өөрийн baseline-ийг хэмжээд (baseline p95 × 1.5) эцэслэн засна, яагаад тэр утгыг сонгосноо энд 1-2 өгүүлбэрээр бичнэ.

## Сценарио 2. Reliability: /pay-ийн эвдрэлийн давтамж

| Хэсэг | Агуулга |
|---|---|
| Тойм | Хэрэглэгч төлбөр төлөхөд хүсэлт амжилттай боловсрогдоно. |
| Системийн төлөв | Сервер хэвийн ажиллаж байна, төлбөрийн гарц (gateway) идэвхтэй. |
| Орчны төлөв | Хэвийн ачаалал: 10 VU, нийт ойролцоогоор 10 хүсэлт/с, 2 минут (~1200 хүсэлт). |
| Гадаад өдөөлт | Хэвийн хэрэглэгч `POST /pay` төлбөрийн үйлдэл хийнэ (халдлага, буруу өгөгдөл биш). |
| Шаардлагатай хариу | Хүсэлт бүр 200 статусаар `{paid:true}` буцаана, 500 алдаа гарахгүй. |
| Хэмжүүр | Error rate (POFOD) < 1%, өөрөөр хэлбэл 100 хүсэлтээс 1-ээс бага нь амжилтгүй. |

SLO: `/pay` error rate < 1% (`http_req_failed`). Энэ API зориудаар ~5% алдаа гаргадаг тул энэ threshold FAIL болно гэж урьдчилан хүлээж байна. Тэр нь тестийн зорилго: SLO-аас бодит байдал хэр зөрж байгааг автоматаар илрүүлнэ.

## Сценарио 3. Availability: серверийн crash ба сэргэлт

| Хэсэг | Агуулга |
|---|---|
| Тойм | Сервер гэнэт зогссон ч богино хугацаанд дахин асаж, хэрэглэгчид цөөн хугацаанд л нөлөөлнө. |
| Системийн төлөв | Сервер хэвийн ажиллаж байгаад (ачаалал дундуур) гэнэт зогсоно. |
| Орчны төлөв | Хэвийн ачаалал: 10 VU, `/cart/add`, 1 минутын тест. Эхний 20 секундэд хэвийн ажиллана. |
| Гадаад өдөөлт | ЭВДРЭЛ: сервер процесс crash хийнэ (`kill`), 10 секундийн дараа гараар дахин асаана. |
| Шаардлагатай хариу | Дахин асмагц систем автоматаар хэвийн хүсэлтүүдийг дахин боловсруулна. |
| Хэмжүүр | Availability (амжилттай хүсэлт / нийт хүсэлт) ≥ 80% 1 минутын тест дотор, сэргэх хугацаа (MTTR, эхний алдаанаас эхний амжилттай хүсэлт хүртэл) ≤ 15 секунд. |

SLO: availability ≥ 80% (энэ 1 минутын crash тестэд), MTTR ≤ 15 с. Урт хугацааны үйлчилгээний SLO (жишээ нь сард 99.9%) нь сард ойролцоогоор 43 минутын эвдрэл зөвшөөрдөг. Тестийн 80% нь 10 секундийн сэргэлтийг тооцсон богино цонхны утга бөгөөд сарын SLO-той шууд харьцуулахгүй.

## Сайн сценариогийн 5 шинжээр өөрийгөө шалгах

| Шинж | Performance | Reliability | Availability |
|---|---|---|---|
| Итгэмжтэй (бодит хэрэглээнд тохирох) | Сагсанд нэмэх нь хамгийн түгээмэл үйлдэл | Төлбөр нь бодит эрсдэлтэй үйлдэл | Crash нь бодит эвдрэлийн төрөл |
| Үнэ цэнэтэй (бизнест чухал) | Удаан сагс = алдагдсан худалдан авалт | Төлбөр амжилтгүй = шууд орлогын алдагдал | Сервер зогсолт = бүх үйлчилгээ зогсоно |
| Тодорхой (хэмжих боломжтой) | p95/p99 мс-ээр | Хувиар | Хувь ба секундээр |
| Нарийн (хэт хийсвэр биш) | 20 VU, ~20 req/s гэж заасан | 10 VU, 2 минут гэж заасан | 20 с дээр crash, 10 с дараа асаах гэж заасан |
| Ойлгомжтой | 6 хэсэг бүр бөглөгдсөн | 6 хэсэг бүр бөглөгдсөн | 6 хэсэг бүр бөглөгдсөн |
